# 薪火 v2 更新说明

> **当前状态**
>
> v2 已于 2026-09-22 晚合并进生产并通过全部验收（标签 `v2-live-20260922`）；情绪 intake 当前运行在 `dual` 双轨观察模式，观察期后再切换到纯自评。前端仍为 mock 演示，真实接口尚未接通。

如果说 v1 主要解决的是“把记忆可靠地留下来、找回来”，那么 v2 往前走了一步：它开始把分散的事件整理成“此刻发生了什么”，让情绪变化有来源、有保鲜期，也让主动唤醒多一层安全约束。

下面只列出已经核实的变化，不把设计目标写成已上线能力。

---

## 01｜event 窗：先把同一件事认出来

| v1 | v2 |
| --- | --- |
| 事件可能分散在不同来源里，查询与去重由各处分别处理 | 增加统一事件层，让不同渠道的事件可以在同一个时间窗中查看 |

v2 增加兼容型 `events` 表，并从既有 `raw_events` 做**非破坏回填**：旧记录保留，新事件层负责统一观察，不用覆盖原始事实。

这扇“事件窗”支持：

- 按时间窗查看事件；
- 按渠道过滤；
- 用 `canonicalId` 与 `dedup_hash` 识别跨渠道的同一事件；
- 保留隐私标记，供后续展示与处理遵守边界。

一句话理解：**不是把所有消息混成一条，而是让系统知道哪些记录其实说的是同一件事。**

---

## 02｜情景帧：给“此刻”留一张快照

新增 `situation_frames` 表，用一帧记录当前场景，而不是让上层每次从长历史里重新猜。

一张情景帧可以承载“现在关注什么、处于什么阶段、接下来如何转场”等近场信息。它由事件驱动写入，并使用绝对时间 `expiresAt` 作为保鲜期。

| 还新鲜 | 已过期 |
| --- | --- |
| 返回当前帧 | 明确返回 `stale` |

过期后不会悄悄续期，也不会把旧场景冒充成现在。

---

## 03｜原生情绪模块 v2：自评负责表达，worker 负责保管

情绪来源改为由**主模型自评**产生。一次自评包含：

- Russell 坐标 `v / a`；
- 变化理由；
- 证据引用；
- 置信度。

worker 不替主模型“猜心情”，只负责平滑、衰减和持久化。

### 情绪配方

基础层使用 8 个 Plutchik 情绪：

| 喜悦 joy | 悲伤 sadness | 恐惧 fear | 愤怒 anger |
| --- | --- | --- | --- |
| 惊讶 surprise | 厌恶 disgust | 期待 anticipation | 信任 trust |

复合情绪不被永久写死：命名规则放在可编辑规则表中，读取时根据当前配方动态命名。关系相关感受放在**独立关系维度组**里，不与八种基础情绪混为一组。

### 不把每次波动都写成大事

只有跨过“显著变化”门槛才新增自评记录，减少细小波动造成的流水账。

### 三种 intake 模式

| 模式 | 用途 |
| --- | --- |
| `worker` | 保留 v1 的 worker 路径 |
| `self_report` | 使用主模型自评 |
| `dual` | 双轨观察，用于比较与过渡（当前生产模式） |

---

## 04｜情绪驱动唤醒：更连续，也更克制

v2 从 Russell 的 `(v, a)` 连续计算 `interval_factor`，而不是只靠几个离散标签决定主动唤醒频率。四个象限仍然提供方向感，但实际调节来自连续坐标。

这里有一条明确的安全条款：当状态落入**极端焦虑象限**（高唤醒、低愉悦）时，系统会硬阻断主动唤醒。此时不把强烈负面状态转化为更频繁的打扰。

---

## 05｜工程防护：能试，也要能退

这次升级先建立了三套相关代码仓库的 Git 基线，并使用统一标签记录边界：

- `pre-emotion-v2-baseline`：v2 改动前基线；
- `native-emotion-v2`：v2 实现节点；
- `v2-live-20260922`：合并上线节点。

运行模式由 `AFFECT_INTAKE_MODE` 控制，可以在 `worker`、`self_report`、`dual` 之间快速切换。这个开关用于秒级回退 intake 路径；数据结构采用兼容、追加式演进，不把“回滚代码”误做成“覆盖新数据”。

上线当晚的实际过程也验证了这套防护：前两次切换尝试分别因一条命令语法和一处文档格式检查被中止，均在改动生产前安全回退，第三次才完整通过全部硬门槛完成切换。

---

## 06｜记忆观察室：把内部状态变成可读界面

仓库新增 `frontend/`，是一套手机优先的“记忆观察室”源码：

| 页面 | 主要内容 |
| --- | --- |
| 状态 | Russell 圆环、情景帧、当前情绪配方 |
| 记忆 | 记忆浏览与召回结果 |
| 记录 | 事件时间线、情绪自述与每日印象 |
| 设置 | 数据说明与工作模型配置 |

界面支持浅色 / 深色模式。当前版本使用**完整虚构的 mock 数据**，所有数据访问集中在适配层，并附有 API 契约，方便后续接入真实后端。

需要特别说明：前端源码入库不等于真实接口已经接通。后端 v2 已上线，但前端仍为 mock 演示，真实接入计划中。

## 从 v1 到 v2，变化在哪里

| v1 的重点 | v2 新增的重点 |
| --- | --- |
| 分层保存、审核、召回与衰减 | 统一事件观察、近场快照与跨渠道去重 |
| worker 参与情绪判断与维护 | 主模型自评，worker 只做平滑、衰减与持久化 |
| 情绪状态参与表达 | 连续坐标参与唤醒节奏，并带极端焦虑硬阻断 |
| 后端机制为主 | 增加手机优先的可读观察界面与 API 适配边界 |

v2 没有推翻 v1 的记忆库，而是在兼容基础上增加新的观察层、状态层和安全控制。

## 现在可以怎样理解它

- **已经完成**：v2 功能实现、隔离测试、生产合并上线（2026-09-22，标签 `v2-live-20260922`）与配套前端源码。
- **当前阶段**：`dual` 双轨观察期（3–7 天），随后评估切换到纯自评模式。
- **尚未声称**：真实前端 API 接通、实体手机端验收。
